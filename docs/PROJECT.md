# OpenTradeLedger（交易账本）项目与架构说明

`OpenTradeLedger` 是本地优先、严格只读的多交易所实盘核账账本与精算复盘系统，支持本机直接运行及跨品牌 NAS（极空间、绿联、飞牛 fnOS、群晖、威联通）Docker 零终端部署。完整安装与使用指南见 [中文 README](../README.zh-CN.md) 与 [English README](../README.md)。

---

## 1. 核心架构边界与安全红线

1. **严格只读网络护栏**：所有交易所适配器统一经由 `security/readonly_guard.py` 发起请求，默认强制拦截任何非 `GET` 请求；仅针对协议设计上纯查询走 `POST` 的公开/账单查询端点（如 Hyperliquid 免私钥公开 `POST /info` 明确枚举的只读 `type`，以及 HTX 合约只读账单查询路径）开启白名单放行并物理封禁任何签名写字段或下单/撤单/提币端点。
2. **本地落盘加密与零遥测**：
   - 交易所 API 密钥保存在 `data/vault.enc`（Fernet 对称加密，权限 `0600`）；AI API Key 与 Bark Push Key 同样在 SQLite 偏好表中加密存储。
   - 局域网 / NAS 访问密码采用 `scrypt` 随机加盐哈希存储于本地，无云端账号依赖、零遥测上报。
3. **闭环恒等式核账（`0.00 U` 误差校验）**：
   - 每个平台分区独立满足：`期初权益 + 净充提划转 + 已实现盈亏 + 手续费与真实返佣 + 资金费 + 未实现盈亏 + 理财/空投/汇率估值项 = 当前真实总净资产`。
   - 任何分平台残差均在「闭环对账」页实时披露，绝不静默吞没差额。

---

### 易币账户归属与 OKX 合约计量

易币以交易所签名接口返回的 UID 绑定本地交易历史。更新密钥时先验证归属，已有账本中无法核对的历史保留供核查。配置表单记录打开时的版本，提交时如配置已更新，页面会提示重新载入。

OKX 同时记录合约张数、合约面值及面值币种。交易详情和成本矩阵使用逐笔成交金额计算费率。旧快照在同步取得适用的规格后可重新计算，缺少可靠分母时显示费率未知。按成交记录区分手续费支出与成交返费，并用交易所已实现盈亏对账。

### 合约持仓与分批平仓

交易列表按账户、合约和方向展示连续持仓。持仓数量归零后重开会产生新记录。适配器从本地成交重建 `position_events`，每次减仓优先采用交易所给出的已实现价差。可验证的线性合约也可按当时的剩余持仓均价计算。时间线显示该次实际费用、释放的开仓费及扣费后的收益。历史缺少成交、合约面值或费用币种换算时，详情保留能查证的总额或张数。

日历按北京时间归集已实现价差和有时间戳的现金变动。已经在开仓日入账的费用仅在复盘时按已平数量分摊。账户的独立结算流水、资金费和日终权益快照按各自来源核算。本地历史在读取时重新计算，原始成交和已有笔记保留在各自账户分区。

## 3. 核心业务口径与模块约定

### 3.1 十一平台全独立对等架构、同交易所多账号与封存机制
- 内置 **Binance**、**OKX (v5)**、**Bybit (v5)**、**Gate**、**Bitget (UTA)**、**MEXC**、**Hyperliquid（免密钥 `0x` 地址）**、**KuCoin**、**BingX**、**火币 HTX**、**EasiCoin（易币）** 11 套完全解耦的适配器包（由 AST 测试强制禁止跨平台互引，且 `SyncManager` / `LedgerService` 零平台硬编码分支）。
- **同交易所多账号与主/子账户识别（`core/account_partition.py`）**：
  - 将交易所协议类型 `adapter_id`（如 `binance`）与本地账本分区主键 `account_id` 解耦：首个账号保持原 `venue_id`（如 `binance`）实现历史数据零迁移无损兼容；同平台新增第 2 个及以上子账户或独立账号自动分配独立分区（如 `binance__<8hex>`），经 `AccountScopedStore` 透明隔离存储、独立退避轮询并独立输出 `0.00 U` 闭环核账卡片。
  - 接入与同步时自动提取远端脱敏 `UID` 及账户角色（OKX `uid` vs `mainUid`、Bybit `isMaster`、Gate `/sub_accounts`、Bitget/HTX `parentId`、KuCoin `isSub`、BingX `/openApi/subAccount/v1/list`、Hyperliquid 主地址与 `subAccounts` 链上子账户自动发现），拦截同交易所重复绑定相同 `UID`（防止总净资产翻倍）以及编辑旧账号误填跨账号密钥（防止历史混账）。
- SQLite 存储按 `account_id` 严格隔离（`otl_venue_kv` / `otl_venue_records`）。移除任意账号时均支持 **「仅解绑凭证，保留本地历史记录（已封存）」** 与 **「彻底删除凭证及该分区全部本地数据」** 两种模式，互不影响同交易所其他账号或其他平台。

已有账本升级后，OKX 和 Bybit 会在有效响应到达时替换旧的异常钱包快照。钱包中的空金额、非数值和明确的零分别处理。遇到无 UID 的旧封存分区，应从原账号行核实归属后再添加其他账户。缺少账户归属证据的笔记保留原键。Hyperliquid 探测子钱包时由服务端比对完整地址，前端缩写只用于显示。

Gate 将可选跟单持仓接口返回的 `permission not open yet` 记录为功能未开放。钱包总余额和现货资金流水独立检查；流水读取失败后保留已有记录，并在下次同步重新回补。

Bybit 首次接入及旧快照升级按七天窗口回补近两年的平仓。最早请求时间按当次请求前的时钟从 730 天边界内移 15 分钟。后续历史页返回可恢复的业务错误时，已读取的平仓按交易标识与旧账本合并，下次同步继续尝试完整回补。易币划转按上游总条数与实际去重结果核对；没有总数时按实际日期进展继续翻页，如连续满页停在同一时间则保留完整性提示。币安密集成交与订单按时间或递增 ID 继续翻页。Hyperliquid 同毫秒满页无法证实收全时提示截断风险。

实盘首次打开且未接入账户时，总览显示添加账户的入口。没有可同步的账户时，手动同步会说明原因，并保留上一次真实同步时间。已封存的历史账单仍可查看。只有主动开启演示模式才会载入示例资产。

已解锁且可见的网页每 15 秒读取服务端会话状态，恢复前台时也会检查。账户配置、连接状态或同步告警变化时重读账户列表与账本，后台同步时间变化时重读当前筛选的账本。浏览器检查只读取 NAS 上的结果。

### 3.2 资产分类与双腿手续费精算口径
- **衍生品合约 vs 正股/代币 vs 全量现货**：
  - 美股永续合约、大宗商品永续与加密永续/交割合约统一归入**合约衍生品**核算，合约账户总权益包含挂单冻结及仓位占用保证金。
  - 股票与代币账户展示正股及有身份依据的股票代币。识别依据是交易所现货目录、发行方在该平台的上市清单，或 HyperCore 的代币编号与名称。现货名称与股票代码相似时，仅凭后缀不会归入美股。尚未收录且缺少目录证据的币种保留在现货。股票模块开关只控制导航，账户净资产仍包含这些持仓。
  - Hyperliquid 现货沿用交易所报价估值。报价对应的交易对近 24 小时成交额为零，或持仓估值大于该交易对全天成交额时，总览单列这部分低流动性估值。资产构成和持仓明细展示报价、成交额及数据来源。早期快照缺少成交额时显示暂无数据，下次成功同步后更新。
  - 首页《当前持仓》独立透出 `spot_wallet_balances` 全账户现货、理财及小额尾仓构成，点击现货或股票行可直接查看明细弹窗。
- **进/出场手续费披露与分批平仓对称排版**：
  - 同一持仓周期（一次建仓 → 分多批止盈/止损平仓归零）统一合并为 **1 条平仓记录**：上方主从区固定维持 **`7:5` 对称比例**并双侧吸顶，左侧列表保持紧凑 4 列确保「实收净盈亏」在 1280px/1440px 桌面视口下 100% 完整可见，仅对真正的分批平仓标 `分 N 笔`（在途减仓标 `已减仓`），普通单笔平仓不附加冗余标签。
  - 右侧交割详情无论分批与否均**常驻直接展示左右对称的「进场手续费 | 出场手续费」双栏**（直显挂/吃单方式、实测 `bps`、各自返佣比例与净费，绝不藏入折叠区）及 5 行持仓结算与复盘笔记；仅当选中分批平仓或在途减仓订单时，在下方横跨 **12 列全宽** 横向铺开「持仓时间线」（每节点同步融合挂/吃单方式、费率、返佣比例、保留原始精度的逐笔手续费、2 位小数价差/净盈亏及可展开原始逐笔成交），彻底消除左右不对称与重复展示。
  - 有逐笔成交拆分的账单独立展示进场腿与出场腿费率（bps）、毛手续费、真实返佣流水及平台币抵扣；原始接口仅提供合并总手续费的记录诚实标注 `分腿费用未知`，同时将已知总手续费准确计入平台费率矩阵（显示综合 bps）与 AI 复盘聚合上下文。

### 3.3 公开带单盯盘、Bark 通知与 AI 外发透明化
- **公开带单盯盘**：免 API Key 监控公开带单员跟单余位与实时成交流推算持仓；重复粘贴已有带单员 ID 仅刷新快照，保留用户既有的监控与提醒开关。
- **Bark 推送与异常防抖**：手机通知统一使用 iOS Bark（支持直接粘贴完整示例链接自动拆解 Server 与 Key）。账户同步网络超时或上游 `5xx` 繁忙采用连续 3 次失败防抖后才触发告警，避免瞬时抖动误报。
- **AI 复盘外发四态溯源**：仅发送聚合统计指标（绝不发送 API Key 或原始订单号），并在界面明确标识 `zero_trades_local`（0 笔成交本地短路未外发）、`local_only`（纯本地精算未外发）、`remote_failed_fallback`（已发请求但远端异常回退本地）与 `remote_llm`（远端模型正常生成）。

新增或更换 Bark 设备时，服务端使用候选配置发送一次验证，收到成功回执后再保存。个人合约账户的提醒依据同步前后新入账的减仓和平仓凭证，同一账户在同一轮合并发送。首次导入历史和重复同步保持静默。一笔止盈委托内的多次成交按同一委托识别。个人提醒为单次投递，公开带单员的仓位和空位通知由各目标的开关控制。

复盘正文、发送明细和交易笔记按实际数据来源区分正式与演示。复盘查询同时匹配来源和统计周期。升级前无法确定来源的报告保存在原 SQLite 表，用户重新生成后即可在对应账本查看新报告。公开健康检查只提供服务与版本信息，逐平台调度及权益详情需要有效的登录会话。

公开带单监控保留最近成功取得的成交快照。接口异常或单向模式缺少起始仓位时，页面标出数据状态；调仓通知按目标、成交与方向区分。Bark 投递状态和已成功的空位提醒冷却保存在本地账本中。

### 3.4 跨品牌 NAS 网页内一键在线升级（OTA）
- 设置页显示后端报告的运行版本。GitHub Release 的版本标签与项目版本一致时，旧版实例可从设置页检测到新版本并下载对应的升级包。
- `core/self_updater.py` 从官方 GitHub Release（含国内镜像自动回退）下载轻量代码更新包，强制校验官方权威 `SHA-256` 哈希后解压至持久化目录 `/app/data/.ota/releases/vX.Y.Z` 并更新 `/app/data/.ota/active.json`。
- `scripts/run_server.py` 启动时优先挂载 `active.json` 指向的版本槽位，无需挂载高危 `docker.sock`，容器重启后版本与全部账本数据 100% 保留。
